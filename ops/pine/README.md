## 為什麼還需要手動這一步

Pine 的驗證分兩段,強度差很多:

| 段 | 內容 | 狀態 |
|---|---|---|
| **邏輯層** | 常數、階梯門檻、公式、視窗長度、ddof、暖機期、na 對齊 | ✅ **已自動化**,CI 每次跑 |
| **執行層** | 編譯、`request.security` 實際行為、TradingView 的資料 | ⬜ **需要這份文件的步驟** |

邏輯層由 `ops/tests/pine_sim.py` 負責:它從 `.pine` **原始檔解析**常數與階梯,
用 Pine 的語義重現計算,再與 `engine.py` 逐月比對。改動 `.pine` 裡任何一個數字
都會讓測試失敗(已用 6 種突變驗證過)。

**但邏輯對不代表跑得起來。** 以下三件事只有真的在 TradingView 上跑過才知道:

1. `.pine` 編不編譯得過(語法、型別、Pine 版本差異)
2. `request.security` 的實際行為是否如假設
3. TradingView 的 VIX/SPX 資料是否與 Yahoo/GitHub 來源一致

第 3 點特別值得留意:**就算程式完全正確,數字還是可能對不上** —— TradingView
可能用不同的 VIX 合約或調整過的 SPX 序列。那不是 bug,是資料源差異。

## 步驟

> ⚠ 以下的 TradingView 介面說明是依一般慣例撰寫的,**我沒有實際操作驗證過**。
> 選單名稱可能因版本或語言設定而不同,請以實際介面為準 —— 動作的**意圖**是對的。

### 1. 開圖表

- 商品:**`SP:SPX`**(標普 500 指數本身。用 `SPY` 或 `ES1!` 數字會不一樣)
- 時間週期:**月線(1M)**

> **這一步錯了,後面全錯。** 所有滾動視窗(SMA12 / z-score 36 / spike 6)的單位
> 都是「月」,套在日線或週線上長度會全部錯亂。

### 2. 貼上指標

1. 打開底部的 **Pine 編輯器**
2. 貼上 [`CashWeightGauge.pine`](CashWeightGauge.pine) 的完整內容
3. 按 **加到圖表**

**確認右上角的資訊表：**

- 顯示 `現金水位儀` + `月線` → ✅ 正確
- 顯示紅色 `⚠ 請切換到月線 1M` → ❌ 回到步驟 1

### 3. 往回捲到 1990 之前 ⚠

**這是最容易漏掉、又最容易讓你白忙的一步。**

TradingView 只匯出**已載入的 bar**。剛開圖時它只載入最近幾年,
直接匯出的話歷史會被截斷,z-score 的 36 個月暖機期吃不到足夠資料,
比對就會出現一堆假的不一致。

往左捲動圖表,直到看見 1990 年附近的 K 線為止。

### 4. 匯出

圖表選單 → **匯出圖表資料…** → 存成 CSV。

匯出檔會包含所有繪製的線,比對腳本只讀「建議現金比重%」那一欄,
其他欄位存在不影響。

### 5. 比對

```bash
python ops/scripts/check_pine_parity.py <你匯出的.csv>
```

### ▲ 差異只在最後一兩個月

**很可能不是 bug。** TradingView 的當月是進行中的 bar,會隨盤中報價一直變;
`engine.py` 用的是有固定截止點的快照。

處理:等當月收完再匯出一次。若歷史月份全部吻合,就是資料時點差異,可以忽略。

暖機期問題 —— 幾乎都是**步驟 3 沒做**。往回捲到 1990 之前再匯出一次。

## 如果編譯失敗 —— 已預先分析的三個候選

離線驗不到編譯,但**可以事先把最可能出事的地方標出來**。
下面三個是靜態審查後認定的高風險點,按可能性排序。
每個都附了確切改法,自己 30 秒就能試,不用先問人。

> 這三個都是**純執行層**的調整,不動任何數字。
> 改完務必回頭跑 `python -m pytest ops/tests/test_pine_sim.py -q` 確認邏輯層還是綠的。

### 候選 1 · `ta.sma` 的 length 型別(最可能)

**錯誤訊息長這樣:**

```
Cannot call 'ta.sma' with argument 'length'='len'.
An argument of 'series int' type was used but a 'simple int' is expected.
```

原因:`sampleStdev` 的 `len` 參數沒寫限定詞,Pine 可能推導成 `series int`,
但 `ta.sma` 的長度要 `simple int`。

**改法** —— 第 44 行附近:

```diff
-sampleStdev(float src, int len) =>
+sampleStdev(float src, simple int len) =>
```

沒先改是因為兩種推導結果我無法離線判定,而**改一個本來就對的東西也可能引入新錯誤**。
若沒出現這個訊息就不要動它。

### 候選 2 · 歷史緩衝不足

**錯誤訊息長這樣:**

```
Pine cannot determine the referencing length of series.
Try using max_bars_back in the indicator() or strategy() function.
```

`indicator()` 已經帶了 `max_bars_back=500`,理論上夠(實際只需 36)。
若仍出現,把它調到上限:

```diff
-     max_bars_back=500)
+     max_bars_back=5000)
```

⚠ 這個錯誤**不一定在加上圖表的當下就出現** —— 它可能在你捲到某段歷史時才爆。
所以做完步驟 3(往回捲)之後要再看一次有沒有紅色驚嘆號。

### 候選 3 · 換行縮排

**錯誤訊息長這樣:** `end of line without line continuation`

`levelColor()` 的巢狀三元運算子跨了四行。Pine 規定續行的縮排**不可以是 4 的倍數**
(4 的倍數被解讀成區塊縮排)。現在用的是 6 格,應該是對的,但若真的報這個錯,
把那四行併成一行即可。

### 不是錯誤、但可能看起來怪的一項

右上角資訊表的「乖離」用了 `str.tostring(mom * 100, "+#.##")`。
`+` 是格式字串裡的字面前綴,**負值有可能印成 `-+2.34`**。
純顯示問題,不影響任何計算,也不影響匯出比對 —— 看到的話忽略即可,或把 `"+#.##"` 改成 `"#.##"`。

## 疑難排解

| 症狀 | 可能原因 | 處理 |
|---|---|---|
| 指標加不上去 / 紅字錯誤 | `.pine` 編譯失敗 | 先看上一節的三個候選。都不是的話再把錯誤訊息貼給 Claude Code |
| 右上角紅色警告 | 圖表不是月線 | 切到 1M |
| `交集不足 24 個月` | 匯出區間太短 | 步驟 3:往回捲 |
| `找不到現金比重欄` | 匯出的欄名不同 | 用 `--cash-column "<實際欄名>"` 指定。腳本會列出所有欄名 |
| 時間欄判讀錯誤 | 匯出格式不同 | 用 `--time-column "<實際欄名>"` 指定 |
| 全部月份都差一點點 | VIX 來源不同 | 指標設定裡把 VIX 來源在 `CBOE:VIX` / `TVC:VIX` 之間切換再試 |
| 差異集中在某幾年 | TradingView 的 SPX 序列有調整差異 | 這是資料源差異,不是程式 bug。記錄下來即可 |

---

## 改動之後要重跑

`.pine` 或 `ops/src/engine.py` 任一方改動後,執行層驗證就失效了,要重跑一次。

邏輯層(CI)會自動抓到不一致,但**它抓不到編譯錯誤** —— 一份邏輯完全正確
卻編譯不過的 `.pine`,CI 會給你綠燈。這是這套驗證已知且無法消除的盲點。
