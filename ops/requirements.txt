# 上界釘到下一個 major 是刻意的。
#
# 黃金基準用 1e-9 精確比對 440 個月,而 CLAUDE.md 明文寫「基準漂移若沒有理由,
# 那就是 bug」。原本全部是無上界的 `>=`,意思是某天 pip 裝到 pandas 3.0、
# rolling/pct_change/groupby 的任一邊界行為改了,基準就會漂 ——
# 而漂移的真正原因會是「裝到新版」,那是最難歸因的一類紅燈,
# 而且它會偽裝成「程式被改壞了」。
#
# 不做完整 lock(pip-compile)的理由:完整 lock 需要有人定期維護,
# 而這個專案的前提就是沒有人定期維護它。釘到 major 是「自動拿到修補、
# 但不會在 major 換版的早上突然變紅」的折衷。
# Node 側已經有 package-lock.json(CI 用 npm ci),Python 側原本沒有等價物。
#
# 2026-10-19 追加的一條規則:**宣告的範圍是一個支援承諾,只能寫進真的驗過的
# major。** 原本不是這樣寫的,於是這個檔案自己有三條假宣告(見下)。
# 下界幾乎不影響 CI 實際跑什麼(`pip install -r` 永遠解析到範圍內的最新版),
# 所以收緊下界不是為了改變 CI,是為了讓宣告變成真的。
pandas>=2.2,<3
# 2026-10-19 從 `>=1.26` 收到 `>=2.1`。兩個獨立理由,都不需要等依賴鎖定的決策:
#   1. `>=1.26,<3` **跨過 numpy 1→2 那次破壞性改版** —— 同一份檔案在
#      2024 年初會解析到 1.26,今天解析到 2.x。一份宣告橫跨兩個 major,
#      等於宣稱兩邊都支援,而從來沒有在 1.x 上跑過這 297 條測試。
#   2. 下界在**維護者自己的機器上裝不起來**:開發機只有 Python 3.13,
#      而 `numpy==1.26.4` 沒有 cp313 wheel,source build 需要編譯器。
# 實測 numpy 2.1.2(開發機)與 2.5.4(乾淨 venv 取範圍上界)下,
# 440 個月黃金基準在 1e-9 都零漂移。驗過的是 2.x,所以宣告只寫 2.x。
numpy>=2.1,<3
requests>=2.31,<3
PyYAML>=6.0,<7
# 直接相依,不是間接:test_reporting.py 用它比對「執行環境 vs 本檔宣告」。
# pytest 本來就會帶進來,但靠別人的相依樹拿到自己要用的東西,
# 正是 pytest-cov 那次的形狀 —— 要用就自己宣告。
# ⚠ 原本寫 `>=23,<27` —— packaging 的版號是 23/24/25/26 各自一個 major,
# 所以那是**跨四個 major**的宣告,而實測過的只有 26.2。兩次第二意見都沒抓到
# 這一條(審的人盯著 numpy),它是「同一個形狀再長一次」的例子。
packaging>=26,<27

# 2026-10-19 從 `<9` 放寬到 `<10`。
# 理由是**宣告原本就與事實不符**,不是為了讓某個檢查過:
#   開發機實際裝的是 pytest 9.1.1,而宣告寫 <9 —— 於是
#   「我在本機跑的 252 passed」和「CI 跑的 252 passed」用的是不同 major,
#   整個專案期間都沒有任何東西發現這件事。
# 實測:252 條測試在 8.x(CI)與 9.1.1(本機)**都全綠**。
# 測試框架的版本不會改變輸出數字,只會改變測試能不能跑 —— 所以它屬於
# 可以寬鬆的那一類。但「寬鬆到沒人管」會變成環境分裂,所以同時加了
# tests/test_reporting.py::test_the_running_environment_matches_requirements。
pytest>=8.0,<10
# pytest-cov 原本【不在】這裡,但 CLAUDE.md 的覆蓋率指令要用它 ——
# 乾淨 clone 照文件跑那行會得到 `error: unrecognized arguments: --cov`。
# 這和 cp950 那次是完全同一類:文件叫使用者跑的指令,在乾淨環境跑不起來。
# 規則:凡是寫進文件要人執行的指令,它需要的東西就必須在這個檔案裡。
# 2026-10-19 從 `>=5.0,<8` 收到 `>=7,<8`。`<8` 本身沒問題,問題是下界:
# 5 / 6 / 7 是三個 major,而實測過的只有 7.1.0。
# ⚠ **不要把 pytest 的跨 major 實測挪用到這裡** —— pytest 的 `<10` 有
# 「252 條測試在 8.x 與 9.1.1 都全綠」當依據,pytest-cov 沒有對應的實測。
# 證據不能轉讓,這是第二意見指出的,而它是對的。
pytest-cov>=7,<8
